## 0. 结论

- **线上冒烟测试（Render）没有做成**：云端的网络策略拒绝连接 `debt-collection-crm-demo.onrender.com`（代理对 CONNECT 返回 403）。线上版本号没确认，线上 A/B 各项都记为**跳过**。线上数据没有任何读写。
- 为了不空手而回，A、B 两部分全部在**本地模拟 Render 的新部署**上逐条执行：新 seed 的库，加 `RENDER=true NODE_ENV=production SESSION_SECRET=…`，这样演示提示条、`trust proxy` 都和线上一样。本地结果：**A 15/15 通过，B 17/17 通过**（B-18 `npm test` 通过 248/248）。这只能说明代码没问题，**不能代替线上确认**。
- 另外发现 **1 个真实缺陷**（D-1，中低）和 5 条低级别观察（O-1…O-5），见第 4 节。
- 判定依据有缺口：**仓库里没有 QA 测试手册 v1.2**（05 号 PDF 第 4.3 节说 `docs/QA测试手册.pdf` 按要求没有提交；全仓库和 git 历史里都找不到）。所以遇到脚本预期和 v1.11.0 不一致时，我按 05 号 PDF 第 2–3 节写的 v1.11.0 规则（G-xx / N-xx）、`src/version.js` 的更新日志和代码判定。每条都注明了依据的编号。手册到位后建议再核对一遍。

**是否可以演示**：本地全部通过。待补线上 A-1 版本号确认和线上 A/B 重跑后才能勾“可以演示”。D-1 只在演示 A-5（调低利率上限）之后才会碰到，A-5 做完立刻改回 18 就不受影响。

## 4. 发现的问题

### D-1 真实缺陷（中低）：调低利率上限后，演示里的计息案件连改催收员都保存不了

- **复现**（本地，`06-artifacts/x-int14b-edit-case2-cap12.png`）：admin 把 Settings 的上限改成 12（即 A-5 的步骤）→ 打开案件 2 的 Edit → 只改 Agent 和 Remark → Save → 报 “Interest rate exceeds the 12% p.a. limit (this loan: 18% p.a.)”，保存失败。
- **原因**：`src/routes/cases.js:206-212` 只在“条款有变化”时检查上限，判断方法是逐项比较 `interest_amount` 等字段的新旧值。演示种子给 Monthly/Annual 贷款存了非零的 `interest_amount`（案件 2 = 228，案件 4 = 364，案件 14 = 1044，案件 20 = 252），而服务端对非 Fixed 贷款一律按 0 处理（`cases.js:200`），所以每次编辑都被当成“条款改了”。用表单新建的贷款存的是 0，不受影响（S-INT-14a 通过）。
- **影响**：设置页红框列出的 D002、D004、D014、D020 恰好都是这类贷款。上限调低之后，红框提示“re-plan them with a restructure”，但这些案件连改派、改备注都做不了，与代码注释“older case can still get a new agent or remark”的本意不符。上限保持 18 时不出现；按 PDF 的要求 A-5 做完马上改回 18，演示不受影响。
- **建议**：比较条款时，非 Fixed 模式忽略 `interest_amount`；或者修正种子数据，让计息贷款的 `interest_amount` 为 0。
