## 4. 发现的问题

### D-1 真实缺陷（中低）：调低利率上限后，演示里的计息案件连改催收员都保存不了（v1.12.0 已修复）

- **手册依据：** INT-14 “编辑一个条款超过上限的旧案件，只改催收员 → 可以保存；只有修改条款时才检查上限”。
- **复现（本地）：** admin 把上限改为 12（即 A-5 的中间状态）→ manager 编辑演示案件 2，只改 Agent 和 Remark → “Interest rate exceeds the 12% p.a. limit (this loan: 18% p.a.)”。表单新建的 18% 案件同样只改催收员，可以保存（S-INT-14a）。
- **原因：** `src/routes/cases.js:200-207` 对非 Fixed 贷款一律按 `interest_amount = 0` 比较条款，但演示种子给 Monthly/Annual 贷款存了非零值：案件 2 = 228、4 = 364、14 = 1044、20 = 252。所以每次编辑都被当成“改了条款”，触发上限检查。
- **影响：** 设置页红框列出的超限贷款正好是这 4 个演示案件，红框提示“re-plan them with a restructure”，但它们连改派都做不了。上限保持 18 时不会出现；线上 A-5 做完立刻改回了 18，本次没有影响线上。
- **建议：** 比较条款时，非 Fixed 模式忽略 `interest_amount`；或者修正种子，让计息贷款存 0。
- 10-27 那次报告也记录了这个问题（D-1）；10-26 那次没有发现。

### D-2 与手册不一致（低）：破产案件 Fulfill 的提示（v1.12.0 已按手册修复）

- **手册依据：** PTP-16 “对 Bankruptcy 案件直接提交 … Fulfill → Fulfill 提示改用 Record Payment 并填原因”。
- **实际：** 返回 “PTP already resolved”。G-19 改为转冻结时自动把 pending PTP 变为 broken，而 `src/routes/ptps.js:16` 先判断“已结束”，再判断破产/已故（第 20 行），所以“Record this payment with a reason instead”这条提示在正常流程里到不了。
- **影响：** 两种情况都会拒绝，不会错记账；界面上冻结案件本来就没有 Fulfill 按钮。处理方式二选一：调换两处判断的顺序，或者按 G-19 后的行为改写手册 PTP-16。
