# 部署上线指南（Debt Collection CRM）

> 记录本项目如何部署到公网、拿到一个**固定不变、24 小时在线**的网址发给顾客体验。
> 当前线上地址：**https://debt-collection-crm-demo.onrender.com**
> 平台：Render（免费版）+ GitHub + UptimeRobot（防休眠）。
>
> **Render 只放演示站。** 正式环境部署在客户自己的服务器上，见第九节。（2026-11-01 决定：原来同样跟着 `master` 自动部署的第二个 Render 服务 `debt-collection-crm.onrender.com` 删除，只保留 demo。）

---

## 一、总体思路

把项目部署到云平台 **Render**，得到一个永久固定的 `https://…onrender.com` 网址：
- **网址永远不变**，顾客随时点开就能看；
- **24 小时在线**，你自己电脑关机也不影响；
- 自带 HTTPS；免费。

配合 **UptimeRobot** 定时访问，避免免费版休眠导致的冷启动。

## 二、代码里已做的"可部署"改动（一次性，已完成）

这些改动已经在仓库里，无需重复做，仅作记录：

1. **`package.json` 加了 Node 版本要求**（`node:sqlite` 需要 Node ≥ 22.5，否则平台给旧版会启动失败）：
   ```json
   "engines": { "node": ">=22.5.0" }
   ```
2. **`src/app.js` 的 session secret 改为读环境变量**（本地仍有默认值）：
   ```js
   secret: process.env.SESSION_SECRET || 'debt-collection-crm-demo-secret'
   ```
3. **新增 `render.yaml`**（Render 一键蓝图）：构建 `npm ci`、启动 `npm run seed && npm start`、锁定 Node 22、自动生成随机 SESSION_SECRET。
4. **`.gitignore` 已忽略 `data/`**：所以数据库文件不进仓库，部署时在服务器上重新 `seed` 生成。

## 三、部署步骤（首次）

### 第 1 步：推代码到 GitHub
在 [github.com](https://github.com) 新建一个空仓库（不要勾选任何初始化项），拿到地址后在项目目录执行：
```powershell
git remote add origin https://github.com/你的用户名/debt-collection-crm.git
git push -u origin master
```

### 第 2 步：在 Render 部署
1. 登录 [render.com](https://render.com)（可用 GitHub 账号登录）。
2. **New + → Blueprint** → 选中该 GitHub 仓库 → Render 自动读取 `render.yaml`。
3. 点 **Apply**，等 2–5 分钟部署完成。
4. 顶部出现固定网址 `https://xxx.onrender.com`。

> 不用蓝图也行：New + → Web Service → 选仓库 → Build 填 `npm ci`、Start 填 `npm run seed && npm start`、Node 版本 22 → Create。

### 第 3 步：验证
浏览器打开网址应看到登录页；用 `manager` / `manager123` 能进系统、看到 20 个演示案件即成功。
（也可访问 `/health` 应返回 `ok`。）

## 五、UptimeRobot 防休眠（已配置）

Render 免费版 15 分钟无访问会休眠，下次访问需冷启动 ~30–60 秒。用 UptimeRobot 每 5 分钟戳一次即可保持唤醒。

设置（[uptimerobot.com](https://uptimerobot.com) 免费账号）：
- **Monitor Type**：`HTTP(s)`
- **URL**：`https://debt-collection-crm-demo.onrender.com/health` （轻量端点，只返回 ok）
- **Interval**：`5 minutes`

> 每月约 730 小时全天候运行，仍在 Render 免费的 750 小时额度内（前提是只部署这一个服务）。

## 六、日常维护

### 更新线上版本（改了代码后）
Render 默认**监听 GitHub，push 即自动重新部署**：
```powershell
# 本地改完代码后
git add <改动的文件>
git commit -m "说明"
git push
```
push 后去 Render 看一眼 Deploy 状态即可（约 2–5 分钟）。也可在 Render 面板点 **Manual Deploy** 手动触发。

### 关于数据
- 线上是**演示环境**：免费版磁盘是临时的，**每次重新部署/重启，数据都会重置**回演示数据。
- 这对 demo 是好事（顾客弄不坏、永远干净），但**不要在这个公开站存真实数据**。
- 真要长期保存线上数据，需要接持久化存储（Render 付费磁盘 / 外部数据库），届时再改。

### 本地开发
本地照常 `npm start`（`http://localhost:3000`），数据在本机 `data/crm.db`，与线上互不影响。本地备份用 `npm run backup`。

## 七、常见问题

| 现象 | 处理 |
|---|---|
| 打开很慢（~30–60 秒） | 冷启动，正常；UptimeRobot 已大幅减少。给重要客户看前自己先点一下焐热。 |
| 打开报 5xx / "Application failed to respond" | 多为还在冷启动 → 等 1 分钟刷新；若持续，去 Render **Logs** 看报错。 |
| 日志出现 `SQLite is not available` 之类 | Node 版本太旧。确认 Render 用的是 Node ≥22.5（`render.yaml` 已锁 22.20.0），Manual Deploy 重来。 |
| 想永远秒开、不休眠 | 升级 Render 付费版（约 $7/月）常驻实例。 |
| 想不公开密码 | 只发登录页、私下给账号；或给整站加访问口令（可后续加）。 |

## 九、正式环境：部署到客户服务器

正式环境不在 Render 上，由客户服务器运行。要点：

| 环境变量 | 填什么 |
|---|---|
| `NODE_ENV` | `production` |
| `SESSION_SECRET` | 一串足够长的随机字符（必填，没有会拒绝启动） |
| `CRM_DB_PATH` | 数据库的绝对路径，放在会长期保留、会备份的磁盘上，如 `/var/lib/crm/crm.db` |
| `PORT` | 程序监听的端口，默认 3000 |
| `TRUST_PROXY` | 前面有一层反向代理（nginx、IIS 等）填 `1`；直接对外不填。没填的话所有人都会被当成代理的 IP：审计日志 IP 全一样，一个人连续输错 5 次密码，所有人都要等 15 分钟 |
| `DEMO_MODE` | 不要设。正式环境默认关闭演示账号页和 Demo Data 工具 |

- 安装：Node ≥ 22.5，`npm ci`；启动：**`npm start`**（不要带 `npm run seed`）。
- **数据不会跟着代码过去。** `data/` 在 `.gitignore` 里，仓库里没有任何数据库文件；用 git 部署，客户服务器第一次启动时会在 `CRM_DB_PATH` 建一个空库。如果是复制整个项目文件夹过去，要排除 `data/`（里面是本机的演示和测试数据）。确实要带数据过去，就把某个 `.db` 文件复制到 `CRM_DB_PATH`。
- 空库没有任何账号。建第一个管理员：`npm run create-admin -- <用户名>`，会显示一次随机密码；登录后在 **Users → Reset PW** 改掉。不需要演示数据。
- 如果想先放演示数据给客户培训：空库执行一次 `npm run seed`（见《正式上线待办》第 1 节）。
- `npm run seed` 会清空全部数据。正式环境下数据库里已经有用户时，它会拒绝执行；确实要清空重来才加 `--force`（`npm run seed -- --force`）。`npm run reset` 会直接删除 `data/crm.db` 再 seed，正式环境不要用。
- 反向代理必须把原来的 Host 和客户端地址传过来，否则登录等所有表单会被拒绝（Cross-site request blocked），IP 也记不对。nginx 示例：
  ```nginx
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
  ```
  HTTPS 在代理上配置；设了 `TRUST_PROXY` 后，经 HTTPS 访问时登录 Cookie 会自动带 Secure。
- 备份：`npm run backup`，备份文件放在数据库同目录的 `backups/` 下，要再复制到别处保存。
- 首次上线和账号处理见 `docs/正式上线待办.md`。
