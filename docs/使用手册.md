# 催收管理系统（Debt Collection CRM）使用手册

> 本手册是项目内的独立文档，可直接分享给内部人员。**它不会在网站里显示。**
> 面向：管理员、催收主管、催收员、财务、审计等内部使用者。

---

## 一、这是什么

一个离线可运行的**内部催收管理系统**。用来管理"欠款案件"从分派、跟进、还款到结案的全过程，并按角色控制每个人能看到、能操作的范围。

- 技术：Node.js + Express + SQLite + 服务端渲染网页，单机即可运行，无需外网。
- 打开方式：浏览器访问 `http://localhost:3000`（本机运行时）。
- 一条命令启动：`npm install && npm run seed && npm start`。

---

## 二、核心概念（先搞懂这几个词）

| 概念 | 含义 | 举例 |
|---|---|---|
| **Debtor 债务人** | **欠钱的那个人**，被催收的对象。 | Ahmad、Sarah Lim 等个人 |
| **Case 案件** | 一笔具体欠款。**把 Debtor + Agent 关联起来**：针对某债务人的、分派给某催收员追的一笔账。 | CASE-2026-0001 |
| **Agent 催收员** | 负责去追讨的员工。案件分派给他，他只看得到自己的案件。 | Lim Wei Sheng |
| **Guarantor 担保人** | **债务人**那边替他做担保的人（在 Debtor 里填）。 | 债务人的担保人 |

> 一句话记忆：**Debtor 是"向谁收钱"，Case 把债务人和催收员连起来。**
>
> **关于 Client（委托方/客户）**：本系统原本支持"外部公司把欠款外包给你催收"的模式（那个外部公司叫 Client）。由于你们目前**全是内部自营业务**，Client 模块已从界面隐藏，所有案件在后台统一归到一个内置的"自营"主体。将来若要承接外部委托，可随时恢复 Client 功能。

## 三、角色与权限

系统有 6 种角色，登录后每个人看到的菜单和数据都不同：

| 角色 | 能做什么 | 数据范围 |
|---|---|---|
| **admin 管理员** | 全部功能 + **用户管理** + 审计日志 | 全部数据 |
| **manager 主管** | 客户/债务人/案件/催收员 + 报表 | 全部数据 |
| **agent 催收员** | 处理案件（记还款、PTP、通话、备注、改状态） | **只看自己的案件**及相关债务人 |
| **finance 财务** | 记录还款、查看报表 | 全部数据 |
| **auditor 审计** | 只读一切 + 审计日志 | 全部数据（只读） |
| **client 客户方** | 只读自己公司的案件 | **只看自己公司的案件** |

> **行级权限**是这个系统的核心保障：催收员和客户方**看不到别人的数据**，从列表、详情到搜索、报表全程生效。

## 四、登录与退出

1. 打开 `http://localhost:3000`，自动跳转到登录页。
2. 输入用户名 / 密码，点 **Sign in**。
3. 右下角显示当前用户和角色；点 **Logout** 退出。
4. 忘记密码 / 需要新账号：**联系管理员**（admin）在「用户管理」里创建或重新启用（见第六节）。

## 五、各功能模块怎么用

### 1. Dashboard 仪表盘（首页）
登录后的首页，按你的角色显示关键指标：今日收款、总欠款、今日到期 PTP、违约 PTP、法务案件、今日新开/结案、逾期任务，以及**最近动态**。管理员/主管还能看到**催收员业绩排行榜**（催收员和客户方看不到排行榜）。

### 2. Debtors 债务人
- 谁能看：admin / manager / agent / finance / auditor（催收员只看自己案件涉及的债务人）。
- 字段：姓名、证件号、公司（债务人自己的公司，选填）、电话、邮箱、地址、雇主、月薪、**风险等级**、**担保人**姓名/电话。
- 点姓名进详情，看该债务人的相关案件。

### 3. Cases 案件（系统核心）
- **列表 + 筛选**：可按状态、优先级、关键字（案件号/债务人名）筛选。催收员只看到自己的案件。
- **新建案件**（admin、manager）：选择 Debtor（债务人）、Agent（催收员），填本金、利息、优先级。系统自动生成案件号 `CASE-年份-序号`，并自动归到内置"自营"主体（无需选客户）。
- **案件详情页**——所有跟进动作都在这里：
  - **记录还款 Payment**：填日期、金额、方式。系统自动重算欠款余额；付清→状态变 `fully_paid`，部分付→`partial_paid`。（`legal/closed` 等终态不会被还款自动改写。）
  - **承诺还款 PTP**：新建一条 PTP（承诺金额+到期日），案件状态自动转 `ptp`；到期后可标记 **Fulfill（已履行）** 或 **Break（违约）**。
  - **通话记录 Call**：记录一次通话结果、时长、备注。
  - **备注 Note**：写一条备注，进入时间线。
  - **改状态 Status**：手动切换案件状态（如 new→assigned→negotiation→…→closed）。
  - **时间线 Timeline**：左侧按时间倒序显示该案件的所有动作，不同类型用不同颜色标记。
  - 只读用户（审计、客户方）能看数据，但**看不到任何操作表单**。

### 4. Agents 催收员
- 谁能看：admin / manager / auditor。
- 每个催收员的**业绩统计**：负责案件数、已收金额、目标达成率（进度条）。列表按已收金额排序。

### 5. Tasks 任务
- 待办任务（跟进、上门、法务、提醒）。催收员只看分配给自己的任务。
- 可新建任务、把任务标记为完成。逾期未完成的任务会用红色标出。

### 6. Reports 报表
- 三张报表（可选日期范围，默认本月至今）：**按客户的收款**、**按状态的欠款**、**催收员业绩**。
- 催收员/客户方看到的是自己范围内的数据，且**看不到催收员业绩排行**。

### 7. Search 搜索
- 顶部全局搜索：按案件号 / 债务人姓名 / 证件号 / 电话查案件。结果同样受行级权限限制。

### 8. Audit Log 审计日志
- 谁能看：admin / auditor。
- 记录所有关键操作：登录/退出、增改客户/债务人/案件/催收员、还款、状态变更、PTP 动作、**新建/停用用户**等。可按操作类型筛选。**只读、不可篡改。**

### 9. Users 用户管理（仅 admin）
见下一节。

## 六、给内部人员开账号（重点流程）

> 本系统**不开放公开自助注册**——那样任何人都能自己开号，对内部系统不安全。账号一律由**管理员统一创建**。

**创建新员工账号：**
1. 用 **admin** 账号登录。
2. 左侧菜单点 **Users** → 右上角 **+ New User**。
3. 填写：
   - **Username 用户名**（唯一，登录用）
   - **Full Name 姓名**
   - **Password 密码**（会加密存储，不会明文保存）
   - **Role 角色**：从 admin / manager / agent / finance / auditor / client 中选。
   - 如果角色是 **agent**：必须**选一个关联催收员**（这样他才能被分派案件、并只看到自己的案件）。
   - 如果角色是 **client**：必须**选一个关联客户公司**（他只看这家公司的案件）。
     （选了 agent/client 角色时，对应的选择框会自动出现。）
4. 点 **Create User**。新账号立即可用，员工就能用它登录了。

**停用 / 启用账号：**
- 在 Users 列表里，点每行的 **Disable / Enable**。停用后该账号无法登录，但历史记录（审计）都保留。
- **不能停用你自己正在用的账号**（防止把自己锁在外面）。
- 系统采用"停用"而非"删除"，以保留完整的审计链条。

**建议的角色分工：**
- 新催收员 → `agent`（关联到对应催收员档案）。
- 催收主管 → `manager`。
- 财务人员 → `finance`。
- 合规/审计 → `auditor`。
- 系统管理员 → `admin`（尽量少，负责开号和维护）。

## 七、数据管理

- **数据存哪**：所有数据在项目目录 `data/crm.db` 这个文件里。只要不重置，重启电脑数据都在。
- **重置演示数据**：`npm run reset` —— ⚠️ **会清空所有数据并重灌演示数据**，你新增的全部丢失。只在想恢复演示状态时用。
- **正常启动**：`npm start` —— 打开现有数据库，**保留**所有数据。以后日常就用这个，别再跑 `reset` / `seed`。
- **备份建议**：想留存数据，先停掉服务，然后把 `data/crm.db` 复制一份（比如加个日期后缀）。误操作后可以还原。

## 八、启动与运行

**首次：**
```
npm install      # 安装依赖（只需一次）
npm run seed     # 生成演示数据（只需一次；已有数据别再跑）
npm start        # 启动，访问 http://localhost:3000
```

**以后每次：** 只需 `npm start`。

- 要求 Node.js ≥ 22.5。
- 停止服务：在运行 `npm start` 的终端窗口按 `Ctrl + C`。

## 九、安全提示

- 这是内部系统，**账号由管理员统一发放**，请勿把管理员账号外借。
- 密码采用加密（bcrypt）存储，数据库里看不到明文。
- 审计日志会记录谁在什么时候做了什么，请如实操作。
- **演示账号**（用户名/密码可在 `/demo-accounts` 这个网址查看，该页面不在登录页显示链接）**仅供演示**。正式使用时，请由管理员在 Users 里创建正式账号，并**停用或修改所有演示账号的密码**。
- 若要把系统开放到公网访问，务必先加访问控制（如整站口令），且不要放入真实敏感数据。

## 十、常见问题

**Q：债务人的"Company"能选已有的公司吗？**
A：目前是自由文本，手动输入即可。它指的是债务人自己名下的公司，和 Client（债主公司）没有关系。要把债务人关联到某个客户，是通过**新建案件**来实现的。

**Q：忘记密码怎么办？**
A：找管理员，在 Users 里可停用旧号、重新创建新号（当前版本通过重建账号处理；如需"重置密码"功能可后续增加）。

**Q：催收员说看不到某个案件？**
A：这是正常的行级权限——催收员只能看到分派给自己的案件。需要他看到，就把案件的负责催收员改成他。
