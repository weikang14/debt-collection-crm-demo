# 催收管理系统（Debt Collection CRM）使用手册

> 本手册是项目内的独立文档，可直接分享给内部人员。**它不会在网站里显示。**
> 面向：管理员、催收主管、催收员、财务、审计等内部使用者。

---

## 一、这是什么

一个离线可运行的**内部催收管理系统**。用来管理"欠款案件"从分派、跟进、还款到结案的全过程，并按角色控制每个人能看到、能操作的范围。

- 技术：Node.js + Express + SQLite + 服务端渲染网页，单机即可运行，无需外网。
- 打开方式：浏览器访问 `http://localhost:3000`（本机运行时）。
- 一条命令启动：`npm install && npm run seed && npm start`。

---

## 二、核心概念（先搞懂这几个词）

| 概念 | 含义 | 举例 |
|---|---|---|
| **Debtor 债务人** | **欠钱的那个人**，被催收的对象。 | Ahmad、Sarah Lim 等个人 |
| **Case 案件** | 一笔具体欠款。**把 Debtor + Agent 关联起来**：针对某债务人的、分派给某催收员追的一笔账。 | CASE-2026-0001 |
| **Agent 催收员** | 负责去追讨的员工。案件分派给他，他只看得到自己的案件。 | Lim Wei Sheng |
| **Guarantor 担保人** | **债务人**那边替他做担保的人（在 Debtor 里填）。 | 债务人的担保人 |

> 一句话记忆：**Debtor 是"向谁收钱"，Case 把债务人和催收员连起来。**
>
> **关于 Client（委托方/客户）**：本系统原本支持"外部公司把欠款外包给你催收"的模式（那个外部公司叫 Client）。由于你们目前**全是内部自营业务**，Client 模块已从界面隐藏，所有案件在后台统一归到一个内置的"自营"主体。将来若要承接外部委托，可随时恢复 Client 功能。

## 三、角色与权限

系统有 5 种角色，登录后每个人看到的菜单和数据都不同：

| 角色 | 能做什么 | 数据范围 |
|---|---|---|
| **admin 管理员** | 全部功能 + **用户管理** + 审计日志 | 全部数据 |
| **manager 主管** | 客户/债务人/案件/催收员 + 报表 | 全部数据 |
| **agent 催收员** | 处理案件（记还款、PTP、通话、备注、改状态） | **只看自己的案件**及相关债务人 |
| **finance 财务** | 记录还款、查看报表 | 全部数据 |
| **auditor 审计** | 只读一切 + 审计日志 | 全部数据（只读） |

> **行级权限**是这个系统的核心保障：催收员**看不到别人的数据**，从列表、详情到搜索、报表全程生效。

## 四、登录与退出

1. 打开 `http://localhost:3000`，自动跳转到登录页。
2. 输入用户名 / 密码，点 **Sign in**。
3. 右下角显示当前用户和角色；点 **Logout** 退出。
4. 忘记密码 / 需要新账号：**联系管理员**（admin）在「用户管理」里创建或重新启用（见第六节）。

## 五、各功能模块怎么用

### 1. Dashboard 仪表盘（首页）
登录后的首页，按你的角色显示关键指标：今日收款、总欠款、今日到期 PTP、违约 PTP、法务案件、今日新开/结案、逾期任务，以及**最近动态**。管理员、主管、财务和审计还能看到**催收员业绩排行榜**（催收员看不到排行榜）。
- **总欠款**是各案件**今日结清额**（Settlement Today）的合计，旁边另列合同余额（含尚未到期的利息）；账龄（按 DPD、按开案天数）也按今日结清额统计。

### 2. Debtors 债务人
- 谁能看：admin / manager / agent / finance / auditor（催收员只看自己案件涉及的债务人）。
- 字段：姓名、证件号、公司（债务人自己的公司，选填）、电话、邮箱、地址、雇主、月薪、**风险等级**、**担保人**姓名/电话。
- 点姓名进详情，看该债务人的相关案件（金额为今日结清额）。
- 修改债务人资料时，审计日志会记下每个字段的改前改后值。

### 3. Cases 案件（系统核心）
- **列表 + 筛选**：可按状态、优先级、关键字（案件号/债务人名）筛选。催收员只看到自己的案件。
- 列表显示每个案件的**今日结清额、逾期金额和 DPD（逾期天数）**；点表头的 **DPD** 按逾期天数从多到少排序，可以当作催收工作队列。Export CSV 导出同样的列（另含合同余额），并带上当前的筛选和排序。
- **新建案件**（admin、manager）：选择 Debtor（债务人）、Agent（催收员），填本金、利息、优先级。系统自动生成案件号 `CASE-年份-序号`，并自动归到内置"自营"主体（无需选客户）。
- **案件详情页**——所有跟进动作都在这里：
  - **记录还款 Payment**：填日期、金额、方式。系统自动重算欠款余额；付清→状态变 `fully_paid`（同时记为当天结案），部分付→`partial_paid`。（`legal/closed` 等终态不会被还款自动改写。）
    - 一笔还款**最多只能付到当天的结清额**（Settlement Today = 剩余本金 + 截至当天的利息）；超过会被拒收，提示里会告诉你最多能付多少。
    - 还款日期不能晚于今天，也不能早于贷款起始日。同一张表单连按两次只会记一笔，第二次会提示“Duplicate submission ignored”。
    - **收据**：在 Records → Payments 里点收据号，打开可打印的收据；修改过的还款，收据上会注明修改时间。
    - **修改 / 作废还款**（admin、manager、finance）：作废时可填写原因。修改或作废前的原记录会永久保留，作废的还款仍列在 Payments 下方的 **Voided** 表里（含作废人、时间和原因），收据号不会再被使用。
  - **条款锁定**：案件一旦有还款或做过重组，Edit Case 里的贷款条款（本金、利息、期限、起始日）和债务人都不能再改；要调整条款请用重组，确实录错的要先作废相关还款。催收员、优先级、备注仍可修改。
  - **金额怎么看**：案件页最大的数字是 **Settlement Today**（今天一次还清的金额）；**Contract Balance** 是按合同算到到期日的剩余应还，含尚未到期的利息。向债务人报欠款时，请报 Settlement Today。
  - **利息怎么算**：Monthly（月利率）按整月计息，每满一个月收“本金 × 月利率”，不足一个月按当月天数折算；Annual（年利率）按天 ÷365；Fixed 是固定利息。
  - **利率上限**：名义年利率不能超过公司设置里的上限（默认、也是最高 18% p.a.，只能调低）；合同总利息不能超过本金；收利息的贷款必须填期限。
  - **承诺还款 PTP**：新建一条 PTP（承诺金额+到期日），案件状态自动转 `ptp`；到期后可标记 **Fulfill（已履行）** 或 **Break（违约）**。
    - 到期日不能早于今天；所有待履行承诺加起来不能超过最后到期日的结清额。
    - 实收少于承诺金额时记为 **partially kept**，不会自动生成新的承诺。
  - **通话记录 Call**：记录一次通话结果、时长、备注。
  - **备注 Note**：写一条备注，进入时间线。
  - **改状态 Status**：手动切换案件状态（如 new→assigned→negotiation→…→closed）。
    - 催收员只能在 New、Assigned、Negotiation、PTP、Partial Paid 之间切换；Fully Paid、Legal、Closed、Cancelled、Bankruptcy、Deceased 只能由主管或管理员设置或解除。
    - 仍有欠款的案件不能标为 Fully Paid。解除 Bankruptcy / Deceased 必须填写原因。
  - **破产 / 已故（Bankruptcy / Deceased）**：不能再新建 PTP、记录通话或重组，只能添加 legal 类任务；改为这两个状态时，待履行的承诺会自动关闭。仍可收款，但必须填写原因（会出现在还款记录、时间线和审计日志里）。
  - **重组 Restructure**（主管、管理员）：生效日当天的还款算在重组之前，之后的还款日期必须晚于生效日；挂账的欠息与新计划第一期同日到期。重组不能提高利率，新增利息加挂账欠息不能超过剩余本金；按月利率或年利率计息的贷款暂不能重组为固定利息（待法律确认）。
  - **时间线 Timeline**：左侧按时间倒序显示该案件的所有动作，不同类型用不同颜色标记。
  - 只读用户（审计）能看数据，但**看不到任何操作表单**。

### 4. Agents 催收员
- 谁能看：admin / manager / auditor。
- 每个催收员的**业绩统计**：负责案件数、已收金额、目标达成率（进度条）。列表按已收金额排序。

- **佣金归属**：每笔还款记在**录入时**负责该案件的催收员名下；之后改派案件，已收的佣金不会转走。

### 5. Tasks 任务
- 待办任务（跟进、法务、提醒）。催收员只看分配给自己的任务。
- 案件改派给新催收员时，未完成的任务一起转过去；案件改为“未分派”时，任务暂时保留在原催收员名下。
- 可新建任务、把任务标记为完成。逾期未完成的任务会用红色标出。

### 6. Reports 报表
- 两张报表（可选日期范围，默认本月至今）：**按状态的欠款**、**催收员业绩**；另可导出逐案明细 CSV。
- 按状态的欠款同时列出**今日结清额**和**合同余额**；逐案明细 CSV 含今日结清额、逾期金额、DPD 和合同余额。
- 每次导出 CSV 都会在审计日志里留一条记录。
- 催收员看到的是自己范围内的数据，且**看不到催收员业绩**。

### 7. Search 搜索
- 顶部全局搜索：按案件号 / 债务人姓名 / 证件号 / 电话查案件。结果同样受行级权限限制。

### 8. Audit Log 审计日志
- 谁能看：admin / auditor。
- 记录所有关键操作：登录/退出、增改客户/债务人/案件/催收员、还款、状态变更、PTP 动作、**新建/停用用户**、**导出 CSV** 等。修改案件、债务人、用户、催收员和公司设置时，记下每个字段的改前改后值。可按操作类型筛选。
- 每次操作的业务改动和它的审计记录一起保存：审计写不进去时，这次操作整笔不生效。审计记录在系统里不能修改。

## 六、给内部人员开账号（重点流程）

> 本系统**不开放公开自助注册**——那样任何人都能自己开号，对内部系统不安全。账号一律由**管理员统一创建**。

**创建新员工账号：**
1. 用 **admin** 账号登录。
2. 左侧菜单点 **Users** → 右上角 **+ New User**。
3. 填写：
   - **Username 用户名**（唯一，登录用）
   - **Full Name 姓名**
   - **Password 密码**（至少 8 位；会加密存储，不会明文保存）
   - **Role 角色**：从 admin / manager / agent / finance / auditor 中选。
   - 如果角色是 **agent**：必须**选一个关联催收员**（这样他才能被分派案件、并只看到自己的案件）。
     （选了 agent 角色时，关联催收员的选择框会自动出现。）
4. 点 **Create User**。新账号立即可用，员工就能用它登录了。

**停用 / 启用账号：**
- 在 Users 列表里点该账号的 **Edit**，把 **Status** 改为 Inactive（停用）或 Active（启用）。停用立即生效：该账号已登录的会话也会被登出；历史记录（审计）都保留。
- **不能停用你自己正在用的账号**（防止把自己锁在外面）。
- 系统采用"停用"而非"删除"，以保留完整的审计链条。

**建议的角色分工：**
- 新催收员 → `agent`（关联到对应催收员档案）。
- 催收主管 → `manager`。
- 财务人员 → `finance`。
- 合规/审计 → `auditor`。
- 系统管理员 → `admin`（尽量少，负责开号和维护）。

## 七、数据管理

- **数据存哪**：所有数据在项目目录 `data/crm.db` 这个文件里。只要不重置，重启电脑数据都在。
- **重置演示数据**：`npm run reset` —— ⚠️ **会清空所有数据并重灌演示数据**，你新增的全部丢失。只在想恢复演示状态时用。
- **正常启动**：`npm start` —— 打开现有数据库，**保留**所有数据。以后日常就用这个，别再跑 `reset` / `seed`。
- **一键备份**：运行 `npm run backup` —— 会把当前数据库复制到 `data/backups/crm-<时间戳>.db`。建议重要操作前先备份一次。
- **还原备份**：把 `data/backups/` 里想要的那个 `.db` 文件，复制覆盖回 `data/crm.db`（还原前先停掉服务），再启动即可。

## 八、启动与运行

**首次：**
```
npm install      # 安装依赖（只需一次）
npm run seed     # 生成演示数据（只需一次；已有数据别再跑）
npm start        # 启动，访问 http://localhost:3000
```

**以后每次：** 只需 `npm start`。

- 要求 Node.js ≥ 22.5。
- 停止服务：在运行 `npm start` 的终端窗口按 `Ctrl + C`。

## 九、安全提示

- 这是内部系统，**账号由管理员统一发放**，请勿把管理员账号外借。
- 密码采用加密（bcrypt）存储，数据库里看不到明文。
- 审计日志会记录谁在什么时候做了什么，请如实操作。
- **演示账号**（用户名/密码可在 `/demo-accounts` 这个网址查看，该页面不在登录页显示链接）**仅供演示**。正式使用时，请由管理员在 Users 里创建正式账号，并**停用或修改所有演示账号的密码**。
- 若要把系统开放到公网访问，务必先加访问控制（如整站口令），且不要放入真实敏感数据。

## 十、常见问题

**Q：债务人的"Company"能选已有的公司吗？**
A：目前是自由文本，手动输入即可。它指的是债务人自己名下的公司，和 Client（债主公司）没有关系。要把债务人关联到某个客户，是通过**新建案件**来实现的。

**Q：忘记密码怎么办？**
A：找管理员，在 **Users** 列表里点该账号的 **Edit** → **Reset password**，输入新密码（至少 8 位）即可，员工用新密码马上能登录。

**Q：催收员说看不到某个案件？**
A：这是正常的行级权限——催收员只能看到分派给自己的案件。需要他看到，就把案件的负责催收员改成他。
